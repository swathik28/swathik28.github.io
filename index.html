What it is

A GenAI system for AT&T, built through Wipro's AI Native Internship, that reviews a proposed network configuration change before it goes live — classifying how risky it is, explaining why in plain language, and drafting a rollback plan in case something breaks. It's meant to give network engineers a second set of eyes on changes to routers, firewalls, and SD-WAN devices across the network.

What I built

Fine-tuned IBM's Granite 4.1 8B language model using QLoRA — a technique that trains small low-rank adapter layers on top of a 4-bit-quantized model, so an 8-billion-parameter model can be fine-tuned on a single GPU instead of a full training cluster. I also helped build WINGS, the orchestrating agent layer that takes a change request, runs it through the fine-tuned model, and returns a risk tier (safe / complex / risky), a plain-language explanation, and a suggested rollback — with a hard rule that a human has to approve before anything actually executes.

Tools & data

Trained on 1,900 synthetic change requests spanning 5 major networking platforms (Cisco IOS, Juniper JunOS, Arista EOS, Palo Alto PAN-OS, VMware VeloCloud) and 7 change types, across a simulated 4-site network topology. Before committing to Granite, we ran a base-model bake-off — it beat TSLAM-4B and Phi-3, the latter of which failed to produce valid, parseable output on 30+ of 285 test cases. The fine-tuned model was merged, quantized to GGUF format, and served through Ollama on a single self-hosted 24GB A10 GPU, entirely inside AT&T's AWS security boundary, so no data or inference calls left the client's environment.

92.3%accuracy, up from 56.5%
0.921macro F1, up from 0.504
98.9%high-risk recall, up from 8.5%
−86%severity-weighted error
Why it matters

Before fine-tuning, the base model got the risk classification right about half the time (56.5% accuracy) and, worse, only caught 8.5% of genuinely high-risk changes — most dangerous changes would have slipped through labeled "safe." After fine-tuning, accuracy jumped to 92.3% and high-risk recall to 98.9%, with zero high-risk changes misclassified as low-risk across all 285 held-out test cases — the one failure mode that actually matters in production. An independent LLM-as-judge review separately scored the model's written explanations 4.30/5 and its recommended actions 4.02/5 for quality.

What it is

A physical robot tasked with finding a specific object somewhere inside an unfamiliar, mapped four-room space — the same core problem search-and-rescue or warehouse robots face: where do you look next, given everything you don't yet know?

What I built

Implemented Bayesian inference for probabilistic localization — instead of committing to a single guess about where it (or the object) is, the robot maintains a full probability distribution and updates it as new sensor readings come in. I integrated PyTorch/TensorFlow object detection so the robot could visually confirm the target once nearby, fusing that with semantic context (weighting kitchen-like rooms higher when searching for a mug, for example) to narrow the search faster than blind exploration.

96%localization accuracy

Why it matters

The system localized correctly 96% of the time across the four rooms, working across a mixed hardware/software team — meaning the perception and decision-making logic had to hold up against a real, physical robot with real sensor noise, not just a clean simulation.
